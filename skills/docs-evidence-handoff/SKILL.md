# Document and hand off

1. Identify the reader, requested artifact and authoritative source revisions. Preserve the user's terminology when the meaning is clear.
2. Explain the resulting behavior, necessary steps and concrete limitations. Check commands and references against the actual system; label unrun examples.
3. For a task handoff, map criteria to evidence, list changed files/revisions, remaining blockers and the next owner/action. Distinguish implemented artifacts from loaded runtime behavior.
4. Keep incident narrative and unrelated history out of always-on instructions. Prefer links to canonical artifacts over copied rules or skill bodies.
5. Verify the document's relevant references and scope. Publishing or sending it outside the assigned workspace needs task authorization.
